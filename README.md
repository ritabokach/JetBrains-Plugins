# Плагины JetBrains — каркас на Compose Multiplatform

Лабораторная 4, веха **В2 «Данные»** (каркас — ЛР1, веха В1). Курс
кроссплатформенной разработки, группа ПИН-252т.

Каталог плагинов [JetBrains Marketplace](https://plugins.jetbrains.com):
список, деталь плагина и страница вендора. Данные живые — из REST API
маркетплейса, моков больше нет.

Проект заведён визардом [kmp.jetbrains.com](https://kmp.jetbrains.com):
Android, iOS на Compose, Desktop, Web на Compose. Первый коммит — вывод
визарда без единой правки, дальше всё написано поверх.

## Запуск

```bash
./gradlew :desktopApp:run                        # ведущий таргет вехи
./gradlew :desktopApp:run -Plocale=en            # то же окно на английском
./gradlew :webApp:wasmJsBrowserDevelopmentRun    # web, бонусом
./gradlew :androidApp:assembleDebug              # Android
```

`-Plocale=en` подменяет только язык JVM, язык системы при этом не трогается.

iOS собирается только на macOS с Xcode — в вехе это бонус, и проверка на него
не смотрит.

## Как разложен код

```
shared/src/commonMain/kotlin/ru/bokach/plugins/
  domain/          модели и интерфейс каталога — не знает ни про UI, ни про сеть
  data/            реализация репозитория поверх сети
  data/remote/     HTTP-клиент (expect/actual), MarketplaceApi, DTO и их маппинг
  utils/           форматирование чисел, suspendRunCatching
  ui/model/        UI-модели и маппинг доменных моделей в них
  ui/navigation/   бэкстек и хост Navigation 3
  ui/components/   переиспользуемые куски: карточка, чипы, шапка
  ui/screens/      по пакету на экран: catalog, detail, vendor. В каждом —
                   composable, состояние, намерения и ViewModel
  composeResources/values, values-en   подписи интерфейса, две локали
```

Несколько решений, которые видно не сразу:

**Маршрут — объект.** `Screen` это sealed interface: `data object Catalog` и
`data class PluginDetail(pluginId)` / `VendorPage(vendorId)`. Опечататься
в аргументе не даст компилятор. Графа маршрутов в Navigation 3 нет — бэкстек
это обычный список, он лежит в `Navigator`, и ViewModel правят его, ничего
не зная про `NavDisplay`.

**Все три спецификации перехода заданы явно.** У `NavDisplay` значения по
умолчанию для не-Android таргетов в гугловском артефакте бросают
`NotImplementedError`, поэтому `transitionSpec`, `popTransitionSpec` и
`predictivePopTransitionSpec` прописаны руками. Заодно это и есть требование
вехи: назад экран должен уезжать не туда же, куда приезжал.

**UI-половина навигации взята у JetBrains** — `org.jetbrains.androidx.navigation3:navigation3-ui`.
Гугловская собрана только под androidJvm, jvm и linux_x64. Рантайм при этом
остаётся гугловский.

**Вниз в composable уходят состояние и колбэк**, а не ViewModel целиком:
отданная целиком ViewModel выводится как Unstable и убивает пропуск
рекомпозиции. Проверяется отчётом компилятора:

```bash
./gradlew :shared:compileKotlinJvm
grep -c "restartable skippable" shared/build/compose_compiler/*composables.txt
```

Все 22 composable проекта — `restartable skippable`.

**Цвет бейджа модели распространения не зависит от темы.** Это единственное
место, где цвет зашит мимо `MaterialTheme`, и это осознанно: зелёный там
означает «бесплатный», а не «светлое оформление».

## Про данные

Источник — публичный REST API маркетплейса, ключ не нужен:

| Что | Запрос |
|---|---|
| страница каталога / поиск | `GET /api/searchPlugins?max=20&offset=N&orderBy=downloads[&search=q]` |
| деталь плагина | `GET /api/plugins/{id}` и параллельно `GET /api/plugins/{id}/rating` |
| вендор | `GET /api/vendors/{name}` |
| плагины вендора | `GET /api/searchPlugins?organization={publicName}` |

**Адрес не в коде.** Базовый URL лежит в `gradle.properties`
(`marketplace.baseUrl`), сборка генерирует из него `ApiConfig` в
`build/generated`. Подменить можно без правки исходников:
`./gradlew :desktopApp:run -Pmarketplace.baseUrl=https://...`.

**Клиент под каждый таргет.** `platformHttpClient` объявлен как `expect`
в `commonMain`, а `actual` у каждой платформы свой движок: OkHttp на
Android, CIO на JVM, Js (fetch браузера) на web — общий для js и wasmJs,
Darwin на iOS. Общая настройка (таймауты, `expectSuccess`) — в
`commonMain`. Маркетплейс отвечает с `Access-Control-Allow-Origin: *`,
поэтому web ходит в API напрямую, без прокси.

**Разбор — `kotlinx.serialization`.** DTO в `data/remote/dto` отдельно от
доменных моделей и от UI-моделей, неизвестные поля игнорируются
(`ignoreUnknownKeys`). Тело ответа читается текстом и разбирается на
`Dispatchers.Default`: API отдаёт `application/graphql+json`, а разбор на
UI-потоке запрещён. Склейка страниц тоже идёт на `Dispatchers.Default`.

**Корутины и отмена.** Состояние каждого экрана — `StateFlow` во
ViewModel. Запросы обёрнуты в `suspendRunCatching`, который
пробрасывает `CancellationException` дальше: отмена не ошибка и экран
ошибки не рисует. В каталоге одна `Job` на все загрузки — новый запрос
поиска отменяет страницу, которая ещё в пути, а не гонится с ней.

**Порядок — по популярности.** Без `orderBy` маркетплейс отдаёт список в
своём смешанном порядке, поэтому каталог, поиск и страница вендора
запрашиваются с `orderBy=downloads`: сверху самые скачиваемые плагины.

**Поиск и пагинация.** Строка поиска уходит в параметр `search` с
debounce 400 мс; пустая строка показывает весь каталог сразу. Страница —
20 записей, больше API не отдаёт (`max` > 20 — ошибка 400). Следующая
страница запрашивается, когда до конца списка остаётся 5 карточек.
Маркетплейс может сдвинуть плагин между страницами, поэтому при склейке
дубликаты по `id` отбрасываются — список использует `id` как ключ.

**Подвохи API.** У плагина без голосов `/rating` всё равно возвращает
усреднённую по сайту оценку — оценка показывается, только если `votes`
не пуст. Фильтр `organization` нестрогий («zhihao» находит «Zhihao
Zhang»), поэтому на странице вендора оставляются только его плагины.
Вендор адресуется в API по полю `name` (у людей это бывает UUID), а
показывается `publicName` — маршрут `VendorPage` поэтому держит строку,
а не число.

**Пропуск рекомпозиции.** При склейке старые карточки остаются теми же
объектами, так что `PluginCard` уже показанных плагинов пропускается.
Все 22 composable проекта — `restartable skippable`.

Данные каталога английские, и это не недоделка: локализуется интерфейс,
а не содержимое. Теги, имена плагинов и вендоров приходят из API как есть.
Вместо иконок плагинов — первая буква имени.

## Чего здесь сознательно нет

Тема, язык и загруженные данные живут в памяти сессии: на диск не
сохраняется ничего, офлайна нет — это В3. Адресная
строка браузера и deep links не трогаются, адаптива под ширину окна нет.
Тесты выключены — они приходят в В4. Всё это вехи В2–В4.
